# Steering Reference

Read only when creating a missing section.

## Product

Record verified purpose, primary users, core capabilities, explicit boundaries, and success measures. Avoid roadmap promises and marketing prose.

## Technology

Record runtime/language versions, package manager, frameworks, important dependencies, architecture boundaries, persistence/integration choices, and commands proven by manifests or configuration. Label inferred architecture as such.

## Structure

Record responsibilities of top-level directories, source/test locations, naming and import conventions observed repeatedly, public boundaries, generated artifacts, and placement rules for new work.

## Validation Checklist

- each fact cites a repository source or is labeled unknown;
- commands and paths exist and use current names;
- existing user guidance remains intact unless directly updated;
- no credential, endpoint secret, personal data, or machine-specific value appears;
- guidance describes this project rather than generic best practices;
- conflicts between documentation and code are reported instead of silently resolved;
- update mode changes only sections supported by new evidence.
