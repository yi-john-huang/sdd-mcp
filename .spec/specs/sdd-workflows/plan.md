# Global SDD MCP setup

## Context

The current installer writes an `sdd-mcp` runtime entry into each repository (`.mcp.json`, `.codex/config.toml`, or `.omp/mcp.json`). The requested end state is a one-time user-level setup for Claude Code, Codex, and OMP so the workflow-control runtime and host-native manual Skills are available in every local project, with clear installation and verification instructions. The setup will be delivered through `bootstrap.sh`; Claude Code permissions remain prompt/policy controlled rather than receiving a global allow rule.

## Approach

1. Make a user-scoped runtime bind to the active repository. Add one workspace-root resolver for `SDDToolAdapter`: use a non-empty `CLAUDE_PROJECT_DIR` when Claude Code supplies it, otherwise retain `process.cwd()` for Codex, OMP, and direct stdio launches. Route every workflow, steering, code-analysis, package-inspection, and template handler through that resolved root so a global Claude server never writes `.spec` under the user configuration directory.
2. Reuse the preserve-first installer without weakening project installs. Add `PreservingWriterOptions { stateDirectory?: string }`; resolve that directory beneath the writer root and use it for the lock, manifest, and backups while leaving the default `.sdd-mcp` behavior unchanged. Add `registerRuntime = true` as the fifth `PreservingWriter.beginTarget(...)` and seventh `TargetInstallSession(...)` parameter; retain it on the session, make `complete(paths?)` require paths only when registration is enabled, and otherwise commit managed files without runtime verification/rollback while retaining any prior registration record. Add `RuntimeRegistrationOptions { configureClaudePermissions?: boolean }` to `registerRuntimeLocked(...)` and `PreservingWriter.installRuntimeRegistration(...)`, defaulting to `true`; global setup passes `false`, so it never creates or changes Claude permission settings.
3. Add `src/cli/setup-global.ts` with `GlobalSetupCLI.parseArgs`, `GlobalSetupCLI.run`, and `mainGlobalSetup`, then route `sdd-mcp-server setup-global [--target <claude-code|codex|omp>]` through `sdd-entry.js` and `src/cli/sdd-mcp-cli.ts`. No `--target` means all three hosts; reject missing, repeated, unknown, or unsupported arguments before writing. Give the CLI a small injected dependency record for environment/home lookup and the no-shell OMP command runner so path tests never depend on the developer machine. Extract the private package-component lookup from `InstallSkillsCLI` into `resolvePackageComponentPath(componentDir: string)` in `src/cli/utils/find-package-root.ts` and reuse it to build the existing managers. For each target, first call `installRuntimeRegistration` with the runtime writer/state and relative config path from step 4. Only after successful registration, run `TargetInstallSession.copySkills` with only `skills`, `registerRuntime = false`, and the Skills writer/state from step 4; do not call a target adapter that emits root guidance. Register the exact running package version as `npx -y sdd-mcp-server@<version>` under `sdd-mcp`; preserve unrelated config/comments, reject malformed or conflicting same-name entries, continue independent hosts, and set a non-zero exit status if any target has a failure or preserved conflict.
4. Resolve user locations and separate ownership namespaces explicitly:
   - Claude Code: define the personal directory as non-empty `CLAUDE_CONFIG_DIR` or `~/.claude`; install Skills under `<personal>/skills` and keep their state under `<personal>/.sdd-mcp/global-skills`. Register runtime in `<personal>/.claude.json` when overridden, otherwise `~/.claude.json`; use `<personal>/.sdd-mcp/global-runtime` for runtime state in both cases.
   - Codex: install Skills under `~/.agents/skills` with state under `~/.agents/.sdd-mcp/global-skills`; register runtime in `${CODEX_HOME:-~/.codex}/config.toml` with state under `${CODEX_HOME:-~/.codex}/.sdd-mcp/global-runtime`.
   - OMP: execute `omp config path` with an argument array, no shell, and accept only one absolute active-agent directory; install `<agent-dir>/skills`, register `<agent-dir>/mcp.json`, and use `<agent-dir>/.sdd-mcp/global-skills` plus `<agent-dir>/.sdd-mcp/global-runtime`. If that command is unavailable or invalid, resolve the effective profile as defined `OMP_PROFILE` first, otherwise `PI_PROFILE`; empty, whitespace, or `default` selects the default profile. Use `PI_CODING_AGENT_DIR` only for the default profile, otherwise derive `~/${PI_CONFIG_DIR:-.omp}/profiles/<profile>/agent`; emit the fallback path and reject a profile containing separators, traversal, or control characters.
   Expand only `~` and `~/...`, canonicalize paths, reject control characters and escape/symlink destinations with the existing containment checks, and never put global ownership/locks/backups in the active repository.
5. Add root `bootstrap.sh` as the source-checkout wrapper. It is POSIX `sh`, fails clearly when `npx` is unavailable, and executes `npx -y "${SDD_MCP_PACKAGE:-sdd-mcp-server@latest}" setup-global "$@"`; this avoids `sudo` and a global npm package install while letting release/debug callers pin a package spec. Include the script in `package.json#files`, preserve executable packaging, and document the equivalent cross-platform command `npx -y sdd-mcp-server@latest setup-global` as the primary path for users who do not have the checkout or POSIX `sh`.
6. Update `README.md`, `docs/INSTALL-GUIDE.md`, and the startup steps in `docs/WORKFLOW.md` to lead with the one-time bootstrap path, list the exact user files above, state that Claude permissions are intentionally unchanged, and show the host checks `claude mcp get sdd-mcp`, `codex mcp get sdd-mcp`, and OMP `/mcp test sdd-mcp` from a directory without a shadowing project entry. Explain that global Skills are local-machine/user-profile assets, Claude cloud/Cowork sessions do not read local personal Skills, OMP named profiles require one setup per profile, and existing project-scoped `sdd-mcp` entries continue to take precedence until users remove them. Keep the existing project installer documented as the repository/team-scoped alternative, not a required follow-up. Add an `Added` entry under `CHANGELOG.md`’s existing `[Unreleased]` section. Link the upstream setup references: Claude Code [MCP](https://code.claude.com/docs/en/mcp) and [Skills](https://code.claude.com/docs/en/skills), Codex [MCP](https://developers.openai.com/codex/mcp/) and [Skills](https://developers.openai.com/codex/skills), and OMP [MCP config](https://github.com/can1357/oh-my-pi/blob/main/docs/mcp-config.md) and [Skills](https://github.com/can1357/oh-my-pi/blob/main/docs/skills.md).
7. Cover the behavior at its boundaries. Add focused tests for path resolution and target filtering; all-host config/Skill installation into temporary user roots; target-specific Skill rendering; preservation of unrelated JSONC/TOML; exact-version upgrades and idempotent reruns; modified-Skill/conflicting-runtime preservation with non-zero status; Claude permission files remaining untouched; OMP profile/fallback paths; the bootstrap wrapper’s package/argument forwarding; npm package inclusion; and `CLAUDE_PROJECT_DIR` taking precedence only when non-empty.

## Critical files & anchors

- `src/cli/setup-global.ts` — new orchestration boundary for user path resolution, rendered Skill installation, runtime registration, and per-target reporting.
- `src/cli/utils/preserving-writer.ts` — ownership/rollback logic that must support files-only global passes without changing project-install defaults.
- `src/cli/tool-support/mcp-registration.ts` — JSONC/TOML merge logic and the Claude permission opt-out.
- `src/adapters/cli/SDDToolAdapter.ts` — currently binds all workflow state to `process.cwd()`; global Claude scope requires `CLAUDE_PROJECT_DIR`.
- `bootstrap.sh` — user-facing one-command wrapper; its delegated command and package spec are the installation contract.

## Assumptions & contingencies

- Global setup means local user scope, not organization-managed configuration or cloud-hosted sessions. Repository-scoped installation remains available for teams that intentionally commit/share target-native assets.
- `bootstrap.sh` defaults to `sdd-mcp-server@latest`, while the resulting runtime entries pin the resolved package version so runtime code and copied Skills stay aligned; rerunning the wrapper performs the preserve-first upgrade.
- Claude tool calls follow existing user, project, and managed permission policy. The setup must not add `mcp__sdd-mcp__*` to any allow list.
- If a same-name runtime entry or managed Skill was changed by the user, preserve it, report the exact path as a conflict, finish independent targets, and exit non-zero. Never overwrite it or add a compatibility alias.
- If `omp config path` cannot run, use the documented environment/default fallback above. If an existing project-scoped `sdd-mcp` definition shadows the new user entry, document removal of only that project entry; do not scan or mutate repositories from global setup.
